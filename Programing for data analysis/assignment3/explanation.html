2.2 SEED — зачем он

SEED = 42
random.seed(SEED)
np.random.seed(SEED)

Случайность возникает когда мы делим данные или выбираем примеры. SEED фиксирует последовательность случайных событий — результат при повторном запуске тот же.

Число 42 не делает модель лучше. Это просто «якорь» воспроизводимости. Один SEED не гарантирует 100% совпадение всех нейросетевых вычислений на разных железках.

Предобработка — сравнение двух вариантов

Пробуем 2 версии и выбираем лучшую по macro-F1 на валидации:

Light (минимальная)

def light_preprocess(text):
    return " ".join(word_tokenize(text.lower()))

Только нижний регистр + токенизация.

Full (полная)

def full_preprocess(text):
    text = text.lower()                                      # регистр
    text = re.sub(r"http\S+|@\w+", " ", text)               # ссылки, @ники
    tokens = word_tokenize(text)
    tokens = [t for t in tokens if t.isalpha() or t == "n't"]  # только буквы + n't
    tokens = [t for t in tokens if t not in stop_words]        # без стоп-слов
    tokens = [lemmatizer.lemmatize(t) for t in tokens]         # лемматизация
    return " ".join(tokens)
Хитрость со стоп-словами: стандартный список содержит not, no, never, n't. Если их удалить, "not good" → "good" и смысл инвертируется. Поэтому: stop_words - {"not","no","nor","never","n't"}.

VADER (словарь + правила)

VADER = Valence Aware Dictionary and sEntiment Reasoner. У каждого слова в словаре есть «эмоциональный заряд». Плюс правила: отрицания, усилители, капс (GOOD!!!), пунктуация.

sia = SentimentIntensityAnalyzer()
score = sia.polarity_scores(text)["compound"]  # от -1 до +1

Из числа в класс — подбор порогов

def vader_label(score, low, high):
    if score <= low:  return 0  # negative
    if score >= high: return 2  # positive
    return 1  # neutral

Перебираем все пары (low, high) с шагом 0.05, считаем macro-F1 на валидации, запоминаем лучшую. Победили: low=-0.05, high=0.40.

Пороги подбираются ТОЛЬКО на val. Если на test — это утечка (мы «подсматриваем» ответы).

TF-IDF + Logistic Regression

Текст → числовой вектор → классификатор. Логистическая регрессия не умеет работать со строками, ей нужны числа.

Что такое TF-IDF?

  • TF (Term Frequency) — сколько раз слово встречается в документе.
  • IDF (Inverse Document Frequency) — обратная частота в корпусе. Слово the есть везде → IDF маленький. Слово terrible редкое → IDF большой.
  • TF-IDF = TF × IDF — слово «весомое», если частое в этом документе и редкое в остальных.
tfidf = TfidfVectorizer(ngram_range=(1, 2), min_df=2)
X_train = tfidf.fit_transform(train_df[text_column])
X_val   = tfidf.transform(val_df[text_column])
X_test  = tfidf.transform(test_df[text_column])
  • ngram_range=(1,2) — слова И пары слов. Для "not very good" признаки: not, very, good, not very, very good.
  • min_df=2 — слово должно встретиться минимум в 2 документах train (отсекаем опечатки/мусор).
  • fit_transform только на train, transform на val/test. Иначе — утечка.

Что такое Logistic Regression?

Несмотря на слово «регрессия» — это классификатор. Учится весам: какое слово повышает вероятность какого класса. wonderful тянет в positive, terrible в negative.

configs = [{"C": 0.5}, {"C": 1.0}, {"C": 4.0}]

C — обратная сила регуляризации. Меньше C — модель проще, менее склонна к переобучению. Проверяем 3 конфигурации, выбираем лучшую по val. Победила C=1.0.

RoBERTa (Transformer)

Transformer — архитектура нейросети для последовательностей. Её главный механизм — attention (внимание): модель смотрит на каждое слово в контексте всех остальных слов предложения.

RoBERTa = Robustly Optimized BERT. Улучшенный BERT: обучен на в 10 раз больше данных, с лучшей стратегией маскирования. Модель cardiffnlp/twitter-roberta-base-sentiment-latest — RoBERTa, дообученная на 124M твитов на классификацию тональности.

device = 0 if torch.cuda.is_available() else -1
clf = pipeline(
    "sentiment-analysis",
    model="cardiffnlp/twitter-roberta-base-sentiment-latest",
    device=device,
    truncation=True, max_length=128,
)
outputs = clf(test_df["text"].tolist(), batch_size=32)
  • device=0 — на GPU если доступен, иначе на CPU
  • max_length=128 — ограничение в токенах (не словах; одно слово может = 2–3 токена)
  • Модель возвращает слова ("positive"), мэпим в числа через label_map
  • Мы её не дообучаем — используем «как есть» (zero-shot)

Метрики

$$\text{Accuracy} = \frac{\text{правильных}}{\text{всех}}$$

Точность (precision) для класса X: из тех, кого модель назвала X, сколько реально X.

Полнота (recall) для X: из всех настоящих X, сколько модель нашла.

$$F_1 = 2 \cdot \frac{P \cdot R}{P + R}$$

Macro F1 — F1 считается отдельно для каждого класса, потом простое среднее. Все классы одинаково важны (в отличие от accuracy, которую вытягивает большой класс).

Confusion matrix

Строки — правильный класс, столбцы — ответ модели. Диагональ — правильные ответы. Остальное — путаница.

→ neg→ neu→ pos
neg4082
neu53510
pos1940

2Автоматическое суммирование

5 статей про детекцию музыкального плагиата → одно общее резюме. Два подхода:

  1. Экстрактивный (TextRank) — выбираем готовые предложения из источников
  2. Абстрактивный (BART) — генерируем новый текст

Данные

reference.txt — эталонное резюме (138 слов). С ним сравниваем результаты обеих моделей через ROUGE.

Чистка текста

text = re.sub(r"\[\d+\]", " ", text)   # удаляем [1], [12], [345]
text = re.sub(r"\s+", " ", text)        # склеиваем множественные пробелы
text = text.strip()                      # пробелы по краям

Деление на предложения

sentences = sent_tokenize(clean(doc))
sentences = [s for s in sentences if len(s.split()) >= 6]  # отсечь обрывки
sentences = list(dict.fromkeys(sentences))                   # дедуп с сохранением порядка

TextRank — экстрактивный метод

Идея: предложения — вершины графа, рёбра — похожесть между ними. Важное предложение — то, которое похоже на многие другие важные. Это по сути PageRank от Google, но для текста.

def textrank_scores(sentences):
    vec = TfidfVectorizer(stop_words="english").fit_transform(sentences)
    sim = cosine_similarity(vec)        # матрица похожестей
    np.fill_diagonal(sim, 0)             # убрать самосвязи
    graph = nx.from_numpy_array(sim)
    return nx.pagerank(graph)            # {idx: score}

Косинусное сходство

Сравнивает направления двух TF-IDF векторов. Для неотрицательных значений: 0 = нет общих слов, 1 = идентичные.

Стратегия отбора

  1. Из каждой из 5 статей — топ-3 предложения по TextRank → 15 кандидатов
  2. Снова TextRank на этих 15
  3. Берём лучшее предложение каждой статьи (5 шт.) + 1 самое важное из остатка → 6 итоговых
  4. Сортируем по (номер_статьи, позиция_в_статье) — для связного чтения
Зачем так сложно: если взять просто топ-6 по score, несколько статей могут вообще не попасть. Эта схема гарантирует представленность.

BART — абстрактивный метод

BART = Bidirectional and Auto-Regressive Transformer. Умеет пересказывать своими словами, объединять, сокращать. Модель facebook/bart-large-cnn обучена на CNN/DailyMail — умеет суммировать новостные тексты.

Проблема: ограничение по длине входа (~1024 токена)

5 статей сразу не влезут. Решение — иерархическое суммирование:

  1. chunks() режет каждую статью на блоки до 400 слов по границам предложений
  2. Для каждого блока — короткое summary (CHUNK_PARAMS)
  3. Склеиваем все промежуточные summary
  4. Прогоняем ещё раз → финальное резюме 112 слов (FINAL_PARAMS)
CHUNK_PARAMS = dict(
    max_length=80, min_length=30,
    num_beams=4,                 # beam search с 4 вариантами
    no_repeat_ngram_size=3,       # запрет повторять любые 3 слова подряд
    do_sample=False,              # без случайности → воспроизводимо
)

Что такое галлюцинация

Модель написала то, чего нет в источниках. Например, добавила точность «99%» или связала число из статьи 1 с методом из статьи 2.

tokens = set(re.findall(r"\b(?:[A-Z][a-z]+|\d+)\b", summary))
# проверяем, что все найденные слова/числа есть в исходных статьях
Это приблизительная проверка. Все отдельные слова могут быть в источниках, но итоговое утверждение всё равно окажется неверным — из-за комбинации.

ROUGE — метрика качества резюме

ROUGE = Recall-Oriented Understudy for Gisting Evaluation.

  • ROUGE-1 — пересечение одиночных слов с эталоном
  • ROUGE-2 — пересечение пар слов (биграмм) → ловит связность
  • ROUGE-L — длина наибольшей общей подпоследовательности → порядок слов
МетрикаTextRankBART
ROUGE-10.4220.336
ROUGE-20.0590.055
ROUGE-L0.2080.188
Длина (слов)167112
ROUGE считает только лексическое совпадение. Он не проверяет: истинность фактов, связность, грамматику, причинно-следственные связи, перефразировки. Высокий ROUGE ≠ правдивое резюме.

3Классификация жанров песен

По словам песни → один из 4 жанров: Country, Hip-Hop, Pop, Rock. Звук не слышим — только текст. Это сразу ограничивает качество: Pop-балладу и Country-балладу лексически отличить тяжело.

Данные

lyrics_raw = load_dataset("Yegor25/lyrics_genre_dataset_medium", split="train")

Важная деталь: колонка genre — это массив строк, а не строка (multi-label датасет). Поэтому .map(dict) падает — используем .apply(pick_genre):

genre_map = {"pop":"Pop", "rock":"Rock", "rap":"Hip-Hop", "hip-hop":"Hip-Hop", "country":"Country"}
def pick_genre(g):
    if g is None or len(g) == 0: return None
    return genre_map.get(str(g[0]).lower().strip("[]"))

Что ещё делаем: фильтр language == "english", отбрасываем песни короче 200 символов, дедупликация по тексту, сэмпл ровно 300 песен на жанр → 1200 всего.

Предобработка

text = re.sub(r"\[.*?\]", " ", text)   # убираем [Chorus], [Verse 1]
# далее: lower, токенизация, isalpha, stop-words, лемматизация, len > 2

После обработки средняя длина сократилась с ~276 до ~131 токена; словарь — с 22 827 до 13 559 слов.

Частотный анализ

Абсолютная vs относительная частота

Тексты Hip-Hop длиннее остальных. Если love встретилось 500 раз в Hip-Hop и 400 в Pop — это ещё не значит что в Hip-Hop оно характернее. Надо смотреть долю:

$$\frac{500}{100{,}000} = 0.5\% \quad\text{vs}\quad \frac{400}{50{,}000} = 0.8\%$$

Лексические категории

categories = {
    "время":  {"morning", "night", "day", ...},
    "эмоции": {"love", "hate", "happy", ...},
    "тело":   {"heart", "eye", "hand", ...},
}

Для каждого жанра — сумма вхождений слов категории, нормализованная на 1000 токенов этого жанра:

$$\text{Частота на 1000} = \frac{\text{число слов категории}}{\text{всего слов жанра}} \times 1000$$

Нормализация обязательна — иначе большой жанр всегда впереди просто за счёт размера.

Редкие слова vs TF-IDF

  • Редкие (hapax, ≤3 вхождений): чаще всего имена, опечатки, случайные формы — малоинформативны
  • TF-IDF: берёт различающую лексику — часто в этом жанре И редко в других
song_tfidf = TfidfVectorizer(min_df=5)
# затем для каждого слова: mean_in (внутри жанра) - mean_out (вне жанра)

Multinomial Naive Bayes

Байесовский классификатор с предположением о независимости слов при известном классе. «Наивное» предположение в реальности не выполняется, но часто даёт хороший baseline.

Типичные ошибки

Чаще всего путаются Pop ↔ Rock (общая лексика любви/жизни/вечеров) и Country ↔ Pop (эмоциональные баллады).

Главный тезис на защите: одного текста недостаточно для определения жанра. Pop-баллада и Country-баллада лексически близки — различия в ритме, инструментах, вокале. Текст — часть сигнала, не весь.

4Идентификация языка

8 языков: kk / ru / en / es / pt / tr / uk / de. Специально взяты похожие пары (ru↔uk, es↔pt) и казахский с его специфическими буквами.

Данные — WiLI-2018

WiLI-2018 (Wikipedia Language Identification) — канонический датасет для языковой идентификации. 500 train + 500 test абзацев на каждый из 235 языков. Источник — Википедия, у каждого примера проверенная ISO 639-3 метка.

url = "https://zenodo.org/record/841984/files/wili-2018.zip"

Из 235 языков берём 8, итого ~1000 примеров на язык после дедупа.

Две стратегии предобработки

A — интенсивная

def preprocess_A(text):
    text = text.lower()
    text = "".join(c if c.isalpha() or c.isspace() else " " for c in text)
    return re.sub(r"\s+", " ", text).strip()
Почему isalpha(), а не [a-z]? isalpha() распознаёт буквы любой письменности — казахские ә, ғ, қ, ң, ө, ұ, ү, һ, і останутся. Если жёстко a-z — весь казахский и русский потеряется.

B — минимальная

def preprocess_B(text):
    return re.sub(r"\s+", " ", text).strip()

Два вида признаков

Слова

TfidfVectorizer(analyzer="word")

Символьные n-граммы (1–3)

TfidfVectorizer(analyzer="char_wb", ngram_range=(1, 3))

Для слова қазақ признаки: қ, а, қа, аз, қаз, аза. char_wb — делает n-граммы внутри слов с учётом границ.

Почему символы круче на коротких текстах: если слово новое/с опечаткой, его просто нет в словаре. Но его характерные буквосочетания (ção, _қа, sch) есть и дают сигнал.

Эксперимент C — Code-switching

Code-switching — смешение языков в одном сообщении: «Мен бүгін университетке бардым, потом поехал домой». Классификатор обучен выдавать одну метку → для смешанного текста результат неустойчив (выигрывает язык с большей долей слов).

Это несоответствие постановки задачи, а не ошибка модели. У текста реально два языка одновременно, а формат ответа требует один.

Главные выводы Задания 4

  • На полных текстах разница между подходами маленькая
  • На коротких текстах char n-grams и fastText — явно лучше
  • Шум сильно бьёт по словесной модели (ищет целые слова), символьная устойчивее
  • Для code-switching нужны мульти-меточные модели или специальные алгоритмы

7. Python-конструкции в ноутбуке

lambda — короткая функция

lambda x: x * 2
# то же что:
def double(x): return x * 2

.apply(func) — применить функцию к колонке

df["clean"] = df["text"].apply(preprocess)
# аналог: df["clean"] = [preprocess(x) for x in df["text"]]

List comprehension

[t for t in tokens if t.isalpha()]
# то же что:
result = []
for t in tokens:
    if t.isalpha():
        result.append(t)

enumerate — индекс + значение

for i, sentence in enumerate(sentences):
    print(i, sentence)
# 0 Hello
# 1 World

zip — соединить по позициям

zip(["a", "b"], [1, 2])
# → [("a", 1), ("b", 2)]

argsort()[::-1][:10] — топ-10 индексов

scores.argsort()      # индексы от меньшего к большему
scores.argsort()[::-1]  # разворот → от большего к меньшему
scores.argsort()[::-1][:10]  # топ-10

axis в numpy / pandas

  • axis=0 — операция по строкам, результат на каждый столбец
  • axis=1 — операция по столбцам, результат на каждую строку
matrix.mean(axis=0)  # среднее каждого признака
probs.max(axis=1)     # максимум вероятности для каждого текста

**kwargs — распаковка словаря в аргументы

params = {"max_length": 80, "num_beams": 4}
summarizer(text, **params)
# то же что:
summarizer(text, max_length=80, num_beams=4)

8. Важные уточнения для защиты

«VADER видит только отдельные слова» — упрощение

VADER использует словарь и правила: отрицания, усилители (very good > good), капс (GOOD), пунктуация (!!!).

«Нет новых слов — нет галлюцинаций» — нельзя так заключать

Модель может собрать неверное утверждение из слов и чисел, которые ВСЕ есть в источниках. Нужна проверка смысла, не только лексики.

«Экстрактивное всегда фактически верно» — не всегда

Дословное копирование не выдумывает фактов, но предложение может потерять контекст. Местоимение it после извлечения теряет антецедент. Склейка из разных источников создаёт ложные связи.

«RoBERTa точно не видела эти твиты» — по коду это не доказать

Код показывает только что мы сами не дообучали её на тесте. Про полное отсутствие пересечения с обучающими данными готовой модели — нужно отдельно проверить.

Высокое качество на одном наборе ≠ качество везде

98.8% на абзацах Википедии не означает такой же результат на: одном имени, SMS, транслитерации, казахско-русском миксе, тексте с опечатками.

9. Итог одной страницей

1Тональность

Три подхода на одной задаче классификации. RoBERTa > TF-IDF+LR > VADER (0.72 / 0.60 / 0.54 macro-F1). Transformer выигрывает за счёт контекста и предобучения.

2Суммирование

TextRank (выбор предложений) vs BART (генерация). TextRank выше по ROUGE (0.42 vs 0.34 ROUGE-1), но это только лексика. BART связнее, но может галлюцинировать.

3Жанры песен

LR > NB (0.51 vs 0.47). Только по тексту определить жанр умеренно — ~51% на 4 класса (случайность = 25%). Pop/Rock путаются сильнее всего.

4Язык

На полных текстах ~99%. На коротких (1–3 слова) — char n-grams и fastText сильно впереди (70–77% vs 60% для слов). Шум и code-switching ломают систему.

Общий алгоритм всех заданий:
подготовить данные → превратить текст в числа/токены → применить модель → измерить метриками → разобрать ошибки руками.
