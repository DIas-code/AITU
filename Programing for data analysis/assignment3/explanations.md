## Общая ячейка в начале

- `%pip install ...` — ставит библиотеки, которых нет в Colab: `datasets` (скачивание датасетов), `transformers` (готовые нейросети), `rouge_score` (метрика ROUGE), `fasttext-predict` (fastText).
- Импорты — всё, что используется в нескольких заданиях: pandas, numpy, matplotlib, nltk, sklearn.
- `nltk.download(...)` — NLTK отдельно скачивает словари:
  - `punkt_tab` — резать текст на слова и предложения;
  - `stopwords` — список стоп-слов;
  - `wordnet` — словарь для лемматизации;
  - `vader_lexicon` — словарь VADER.
- `SEED = 42` — «зерно» случайности. Везде, где что-то выбирается случайно, передаём `random_state=SEED`, и при каждом запуске результат одинаковый. Это **воспроизводимость**.

### Термины, которые встречаются везде

| термин | что это |
|---|---|
| **токен / токенизация** | токен — кусочек текста (слово или знак); токенизация — разрезать текст на токены |
| **стоп-слова** | частые служебные слова без смысла: the, is, and, you |
| **лемматизация** | привести слово к словарной форме: `cars` → `car` |
| **TF-IDF** | превращает текст в числа. Вес слова высокий, если оно частое в этом тексте и редкое в остальных |
| **fit / transform** | `fit` — изучить данные (составить словарь, посчитать веса); `transform` — применить к новым данным. `fit` делаем только на train |
| **train / validation / test** | на train модель учится, на validation выбираем настройки, на test — финальная честная проверка |
| **stratify** | при делении на части сохранить доли классов |
| **утечка данных** | когда модель при обучении «видит» тестовые данные — результат получается нечестно завышенным |
| **accuracy** | доля верных ответов |
| **precision** | из тех, кого модель назвала классом X, сколько правда X |
| **recall** | из всех настоящих X сколько модель нашла |
| **F1** | среднее между precision и recall |
| **macro** | считаем метрику для каждого класса отдельно и берём простое среднее — все классы одинаково важны |
| **confusion matrix** | таблица: строки — правильный класс, столбцы — ответ модели, на диагонали — верные ответы |

## Задание 1. Тональность текста

### Шаг 1. Данные
- `load_dataset("cardiffnlp/tweet_eval", "sentiment")` — скачивает твиты, размеченные на 3 класса: 0 negative, 1 neutral, 2 positive.
- Берём часть **test**. Причина: модель RoBERTa из шага 5 дообучалась на части train. Если проверять её на тех же твитах, это была бы утечка данных.
- `drop_duplicates(subset="text")` — удаляем одинаковые твиты **до** деления, иначе один твит мог бы попасть и в train, и в test.
- `groupby("label").sample(n=1000)` — по 1000 твитов каждого класса: 3000 текстов, классы равны.
- `train_test_split` два раза: сначала 70% / 30%, потом 30% пополам → 70 / 15 / 15 (2100 / 450 / 450).
- `.copy()` — делаем независимые таблицы, чтобы потом спокойно добавлять в них столбцы.

### Шаг 2. Предобработка
- `stop_words = ... - {"not", "no", "nor", "never"}` — стоп-слова **без отрицаний**: «not good» не должно превратиться в «good».
- `simple_preprocess` — простая обработка: нижний регистр + токенизация.
- `full_preprocess` — полная: нижний регистр → `re.sub` удаляет ссылки, `@user` и символы → токенизация → без стоп-слов → лемматизация.
- **Сравнение:** обе версии подаём в одну и ту же модель (TF-IDF + LR) и смотрим macro-F1 на валидации. Простая 0,609, полная 0,597 → в шаге 4 берём простую (`best_column`).
- VADER и RoBERTa получают **исходный** текст: им нужны отрицания, `!!!`, КАПС, смайлики.

### Шаг 3. VADER
- `sia.polarity_scores(text)["compound"]` — итоговая оценка тональности от −1 до 1.
- `vader_label(score, threshold)` — больше порога → positive, меньше −порога → negative, между → neutral.
- Цикл по порогам 0,05 … 0,5: для каждого считаем macro-F1 **на валидации** и запоминаем лучший. Лучший — 0,05.
- Лучший порог применяем к тесту: accuracy 0,531, macro-F1 0,528.

### Шаг 4. TF-IDF + Logistic Regression
- `vectorizer.fit_transform(train)` — словарь и веса строятся только по train; `transform(val/test)` — только применяются.
- **Logistic Regression** — модель, которая по числам TF-IDF учится предсказывать класс.
- **C** — гиперпараметр, сила регуляризации: маленький C — модель проще, большой — сильнее подстраивается под train. Проверяем C = 0,1 / 1 / 10, лучший по валидации C = 1.

### Шаг 5. Transformer
- `pipeline("sentiment-analysis", model=...)` — готовая модель RoBERTa, уже обученная на твитах. Мы её **не обучаем**, только применяем.
- `device=0` — видеокарта, если есть (в Colab T4 GPU).
- Модель отвечает словами (`"negative"`), а в датасете числа → `label_map` переводит.
- `del classifier` — удаляем модель из памяти, она больше не нужна.

### Шаг 6. Оценка
- Для каждой модели считаем accuracy, precision, recall, F1 (macro) → таблица.
- `ConfusionMatrixDisplay.from_predictions` рисует матрицу ошибок.
- Итог: VADER 0,528, TF-IDF + LR 0,605, Transformer **0,718** (macro-F1).

### Шаг 7. Ошибки
- `wrong` — твиты, где ошиблась хотя бы одна модель (`|` — «или»).
- `.sample(n=10)` — 10 случайных примеров; рядом метка и ответы всех трёх моделей.
- В выводе разобраны причины: сленг («KILLING ME» = нравится), сарказм, отрицания, предметные слова.

## Задание 2. Суммирование

### Шаг 1. Данные
- Пять статей о поиске музыкального плагиата: `article1.txt` … `article5.txt`, каждая больше 250 слов. Эталонное резюме — `reference.txt` (138 слов).
- Если файлов нет рядом (как в Colab), `urllib.request.urlretrieve` скачивает их с GitHub.
- `len(text.split())` — число слов.

### Шаг 2. Предобработка
- `clean` удаляет мусор из PDF:
  - символ `\x02` — остаток переноса слова;
  - колонтитулы;
  - ссылки на литературу `[12]`;
  - маркеры `•`;
  - лишние пробелы.
- `sent_tokenize` — режет на предложения.
- Убираем обрывки короче 5 слов и повторы (`dict.fromkeys` оставляет только первое вхождение).
- Исходные предложения сохраняются — резюме собирается из них.

### Шаг 3. Экстрактивное резюме (TF-IDF)
- `sentence_scores`: каждое предложение → вектор TF-IDF (без стоп-слов, в нижнем регистре); **значимость = сумма весов слов** предложения.
- `scores.argsort()[::-1][:3]` — номера трёх предложений с наибольшей значимостью. `sorted(...)` — вернуть их в порядке, как в статье.
- 5 статей × 3 = **15 кандидатов**. Из них тем же способом берём **6** и оставляем в исходном порядке.

### Шаг 4. Абстрактивное резюме (BART)
- **BART** (`facebook/bart-large-cnn`) — нейросеть, которая сама пишет пересказ.
- Ограничение: на вход максимум 1024 токена. Стратегия — **иерархическое суммирование**:
  1. делаем короткое резюме каждой статьи;
  2. склеиваем пять резюме;
  3. делаем резюме этого текста.
- Параметры генерации зафиксированы:
  - `max_length` / `min_length` — длина в токенах;
  - `num_beams=4` — модель перебирает 4 варианта и берёт лучший;
  - `do_sample=False` — без случайности, результат каждый раз одинаковый.
- Итог — 125 слов.

### Шаг 5. ROUGE
- **ROUGE-1** — общие слова с эталоном, **ROUGE-2** — общие пары слов подряд, **ROUGE-L** — самая длинная общая последовательность слов.
- Берём F-меру (`fmeasure`): баланс между «сколько эталона покрыто» и «сколько лишнего».

### Шаг 6. Качественный анализ
Таблица по 5 критериям, три различия подходов и пример, где BART смешал источники и пропустил темы.

## Задание 3. Жанры песен

### Шаг 1. Данные
- Датасет большой (468 тыс. песен), поэтому фильтруем через `lyrics.filter(...)` — `datasets` работает с диском, не загружая всё в память.
- Оставляем английские песни с одним жанром. Для каждого жанра: `shuffle` + `select(range(400))` — 400 случайных песен.
- `is_english` — проверка языка: метка «english» иногда ошибочна. Если стоп-слов английского меньше 25% слов текста — это не английский. Удалено 73 песни.
- `drop_duplicates` + `sample(n=300)` → по 300 песен на жанр.
- `describe()` — статистика длины: среднее, медиана (50%), минимум, максимум.

### Шаг 2. Предобработка
`preprocess_lyrics`:
1. нижний регистр;
2. удаление пометок `[Chorus]`;
3. токенизация;
4. только слова из букв длиной от 3 символов — отсекаем `na` (от gonna), `im` (от I'm);
5. без стоп-слов;
6. лемматизация.

Результат — список слов `tokens` и строка `clean` для TF-IDF.

### Шаг 3. Частоты
- `Counter` — считает, сколько раз встретилось каждое слово.
- `most_common(10)` — топ-10. Относительная частота = слово / все слова жанра × 100%.
- `ax.bar` — столбчатая диаграмма для каждого жанра.

### Шаг 4. Категории
- Три словаря слов: время, эмоции, тело.
- Для жанра считаем, сколько раз встречаются слова категории, и делим на все слова жанра × 1000 → **частота на 1000 слов**. Нужно, потому что Hip-Hop вдвое длиннее.

### Шаг 5. Редкие и характерные слова
- Редкие — `count <= 3` внутри жанра.
- Характерные:
  - TF-IDF по каждой песне;
  - средний вес слова в песнях жанра минус средний вес в остальных песнях;
  - топ-10 по этой разнице — слова, которые есть именно в этом жанре.
- `min_df=5` — слово должно встретиться хотя бы в 5 песнях.

### Шаг 6. Классификация
- 80 / 20 со стратификацией; TF-IDF `fit` только на train.
- **Multinomial Naive Bayes** — считает, насколько вероятно каждое слово в каждом жанре, и выбирает самый вероятный жанр.
- **Logistic Regression** — учит вес для каждого слова.
- Исполнителей в датасете нет — разделение по исполнителям невозможно.

### Шаг 7. Оценка
- Accuracy и macro-F1 обеих моделей, две матрицы ошибок.
- Цикл с `zip` печатает первые 5 ошибок Logistic Regression: правильный жанр, ответ модели и начало текста.

## Задание 4. Определение языка

### Шаг 1. Данные
- WiLI-2018 скачивается архивом, `zipfile` распаковывает.
- Тексты (`x_*.txt`) и метки (`y_*.txt`) читаем построчно.
- 6 языков: kk, ru, en, es, pt, de. Близкородственная пара — es и pt. `LANGS` переводит коды WiLI (`kaz`) в короткие (`kk`).
- Удаляем дубликаты, делим 80 / 20 со стратификацией.

### Шаг 2. Две обработки
- **A** — нижний регистр, всё, что не буква и не пробел, → пробел. `c.isalpha()` понимает буквы **любого** алфавита, поэтому ә, қ, ң и т.д. остаются.
- **B** — только лишние пробелы (`" ".join(text.split())`).
- Печатаем казахский пример — видно, что буквы на месте.

### Шаги 3–4. Признаки и модели
- Два способа признаков:
  - `TfidfVectorizer(analyzer="word")` — признаки-слова;
  - `TfidfVectorizer(analyzer="char", ngram_range=(1, 3))` — признаки — кусочки по 1–3 символа (`қ`, `ің`, `ção`).
- Три вложенных цикла: обработка (A, B) × признаки (слова, символы) × модель (NB, LR) = **8 вариантов**. Для каждого — accuracy и macro-F1.
- `trained[...]` — сохраняем векторизатор, модель и предсказания, чтобы использовать дальше.
- **fastText lid.176** — готовая модель на 176 языков; `ft.predict` возвращает метку вида `__label__kk`, убираем `__label__`. Работает в Colab; на Windows с Python 3.14 не ставится.

### Шаг 5. Лучшая конфигурация
- Сортируем таблицу по macro-F1 и берём первую строку: B + символы + LR (0,988).
- Рисуем её матрицу ошибок.

### Шаг 6. Устойчивость
- **A (короткие тексты):** берём первые 3 и первые 10 слов каждого тестового текста. Слова — 0,667 → символы — 0,803 на 1–3 словах.
- **B (опечатки):** `add_typos` — каждая буква с вероятностью 10% удаляется, получает лишнюю букву или заменяется. Новые буквы берутся из того же текста. Точность 0,988 → 0,981.
- **C (смешение):** 30 предложений казахский + русский. `predict_proba` даёт вероятность каждого языка; максимальная — это **уверенность** модели.

### Шаг 7. Ошибки
- Ошибки на полных текстах (14 из 1185) — в основном английские ссылки внутри португальских и русских статей.
- Ошибки на 1–3 словах (233 из 1185) — даты, имена, общие слова.
- Почему символы лучше на коротких текстах: в 1–3 словах может не быть ни одного знакомого слова, а кусочки букв есть всегда.
