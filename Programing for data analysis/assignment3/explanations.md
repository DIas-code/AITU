### Термины

| термин | что это |
|---|---|
| **токен / токенизация** | токен — кусочек текста (слово или знак); токенизация — разрезать текст на токены |
| **стоп-слова** | частые служебные слова без смысла: the, is, and, you |
| **лемматизация** | привести слово к словарной форме: `cars` → `car` |
| **TF-IDF** | превращает текст в числа. Вес слова высокий, если оно частое в этом тексте и редкое в остальных |
| **n-граммы** | `ngram_range=(1, 2)` — признаками будут и отдельные слова, и пары слов подряд («not good») |
| **fit / transform** | `fit` — изучить данные (словарь, веса); `transform` — применить. `fit` только на train |
| **train / validation / test** | на train учимся, на validation выбираем настройки, на test — финальная проверка |
| **stratify** | при делении сохранить доли классов в каждой части |
| **утечка данных** | модель при обучении «видела» тестовые данные — результат нечестно завышен |
| **accuracy** | доля верных ответов |
| **precision** | из тех, кого модель назвала классом X, сколько правда X |
| **recall** | из всех настоящих X сколько модель нашла |
| **F1** | среднее между precision и recall |
| **macro** | метрика для каждого класса отдельно, потом простое среднее — все классы одинаково важны |
| **confusion matrix** | строки — правильный класс, столбцы — ответ модели, диагональ — верные ответы |

## Задание 2. Суммирование

### Шаг 1. Данные
- Пять статей о поиске музыкального плагиата (`article1.txt` … `article5.txt`, 316–700 слов) и эталон `reference.txt` (138 слов).
- Если файлов нет рядом (как в Colab), `urlretrieve` скачивает их с GitHub.
- Таблица: источник и количество слов (`len(text.split())`).

### Шаг 2. Предобработка
- `clean` убирает:
  - символ `\x02` (остаток переноса из PDF);
  - колонтитулы;
  - ссылки `[12]`;
  - лишние пробелы.
- `sent_tokenize` — на предложения.
- Обрывки короче 6 слов и повторы (`dict.fromkeys`) убираются.
- Исходные предложения сохраняются.

### Шаг 3. Экстрактивное резюме (TextRank)
- `textrank_scores`:
  1. каждое предложение → TF-IDF вектор (без стоп-слов);
  2. `cosine_similarity` — насколько каждая пара предложений похожа (0 — ничего общего, 1 — одинаковые);
  3. строим **граф**: предложения — вершины, похожесть — вес связи (`nx.from_numpy_array`);
  4. `nx.pagerank` — важность каждого предложения: важно то, что похоже на многие другие.
- По 3 самых важных из каждой статьи → **15 кандидатов**. `sorted(top3)` — в порядке, как в статье.
- Из 15 снова TextRank. Чтобы были все статьи: лучшее предложение каждой статьи (5) + ещё одно самое важное (1) = **6**. Сортировка по статье и месту в статье — порядок для чтения.

### Шаг 4. Абстрактивное резюме (BART)
- `facebook/bart-large-cnn` — нейросеть, которая сама пишет пересказ. На вход максимум 1024 токена.
- **Иерархическое суммирование:**
  1. `chunks` режет каждую статью на куски до 400 слов по границам предложений; маленький хвост (меньше 100 слов) приклеивается к предыдущему куску;
  2. для каждого куска — короткое резюме (`CHUNK_PARAMS`);
  3. все резюме склеиваются → итоговое резюме (`FINAL_PARAMS`, 112 слов).
- Параметры зафиксированы:
  - `num_beams=4` — перебор 4 вариантов;
  - `no_repeat_ngram_size=3` — без повторов фраз;
  - `do_sample=False` — без случайности.
- Проверка фактов: ищем в резюме слова с большой буквы и числа, которых нет ни в одной статье. Не нашлось — новых фактов BART не придумал.

### Шаг 5. ROUGE
- **ROUGE-1** — общие слова с эталоном, **ROUGE-2** — общие пары слов, **ROUGE-L** — самая длинная общая последовательность. Берём F-меру.
- Экстрактивное: 0,422 / 0,059 / 0,208. Абстрактивное: 0,336 / 0,055 / 0,188.

### Шаг 6. Качественный анализ
Таблица по 5 критериям, три различия и пример, где BART смешал источники и пропустил темы (MFCC, ритм).
